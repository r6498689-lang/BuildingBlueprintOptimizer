# 2.0.0 独立插件拆分验证

验证日期：2026-10-24。环境：Windows、UE 5.6.1、Visual Studio 2022。

## 源码与模块

- 创建插件模块：`BuildingBlueprintCreator`。不包含已有蓝图优化入口或优化队列，未依赖优化插件。
- 优化插件模块：`BuildingBlueprintOptimizer`。不包含 Actor 转蓝图、按父级创建入口或创建接口，未依赖创建插件。
- 优化插件使用独立的反射类、结构体和缩略图类名；保留旧建筑资产标记用于输入兼容识别。
- 两个插件均保留引擎 Datasmith Content 依赖，仓库未包含引擎源码或项目素材。

## 编译与用例

分别在只安装其中一个插件的隔离工程编译 Editor 模块，均成功。自动化验证使用 NullRHI：

| 工程 | 用例 | 结果 |
| --- | --- | --- |
| 仅创建插件 | `BuildingBlueprintCreator.ParentBatch` | Success，0 错误、0 警告 |
| 仅创建插件 | `BuildingBlueprintCreator.ParentBatchReload` | Success，0 错误、0 警告 |
| 仅优化插件 | `BuildingBlueprintOptimizer.Standalone` | Success，0 错误、0 警告 |
| 两插件共同加载 | `BuildingBlueprintOptimizer.Standalone`，含 `-BBCExpectCreator` | Success，0 错误、0 警告 |

优化独立用例通过引擎原生接口生成输入夹具；未调用创建插件。验证空输入/普通蓝图拒绝、兼容建筑识别、两个重复零件转为一个 ISM 的两个实例、源层级保留、输出加载与实例化、模型引用保留，以及创建模块独立缺席或共同加载的状态。

创建插件的已有测试须以 `-BBCValidation` 显式启用。优化独立测试须在专用工程加 `-BBCSplitValidation`，通过 `Automation RunTests BuildingBlueprintOptimizer.Standalone` 运行；共存验证另加 `-BBCExpectCreator`。测试会在专用工程 `/Game` 下创建夹具，不应在工作工程运行。

以上是用例报告结果，不代表完整启动日志没有其他环境信息。构建工具提示本机 MSVC 并非引擎首选版本，隔离工程关闭默认引擎插件时也存在启动诊断。本次未对大型项目性能、Nanite 内存变化、GUI 截图及完整旧版回归集重新验收。

## 兼容说明

创建仓库保留旧提交历史；1.9.x 历史提交为合并版，main 分支的 2.0.0 已拆分。旧版调用 `UBuildingBlueprintLibrary::OptimizeBuildingBlueprint...` 的代码需改用优化插件的 `UBuildingBlueprintOptimizerLibrary` 接口。正常建筑资产保留原生 Actor 父类和识别标记，不要求同时加载两个插件。
